# Fix OTP length mismatch (email sends 8 digits, login accepts 6)

## What's happening

The login screen's code box accepts exactly 6 digits (Email OTP, Mobile OTP and emergency login boxes are all 6 slots). The backend auth service is currently generating an 8-digit email code, so the code in the email can never be fully entered.

## Fix

Set the backend auth email OTP length back to 6 digits, so the emailed code matches the 6-slot login input. Nothing changes in the login UI, the email template, or the mobile OTP flow (mobile codes are generated by our own function and are already 6 digits).

## Steps
1. Update the auth email OTP length setting to 6 on the backend.
2. Trigger a real email OTP for a test address and confirm the delivered code is 6 digits.
3. Confirm sign-in completes with that code.

## Fallback
If the backend refuses to change the OTP length, the alternative is to widen the Email OTP input on the login screen to 8 slots (mobile/emergency stay 6). This would only be done if step 1 cannot be applied, and I'd tell you before switching approaches.
