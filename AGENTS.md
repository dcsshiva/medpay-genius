# Architecture decisions
- Keep Overview unit-attendance aggregation in a pure module with shared daily denominators; stacked unit contributions must preserve the overall attendance percentage.
- Keep retired doctor, visit, and non-payroll payment screens behind one shared client-side screen filter in navigation, permissions UI, and tab dispatch; this preserves historical data and backend privileges while making the remix staff-focused.
- The app UI is the approved Selvantra HRMS prototype, ported verbatim: `scripts/prototype/index.html` → `scripts/port_prototype.py` (asserted text patches) → `src/hrms/prototype.ts`. Change screens/logic by editing the patch script (or the prototype) and regenerating — never hand-edit `prototype.ts`.
- `src/hrms/HrmsApp.tsx` hosts it (routes `/`, `/dashboard`, `/auth`); data lives in the `hr_*` tables (migration 0013, demo seed 0014) and is saved by diffing the in-memory collections (`src/hrms/data.ts`). Staff sign in as `<code>@staff.westmed.local` via the `hr-manage-login` edge function; admins use their WestMed accounts. Old screens stay at `/classic`.
- Payslip figures (earnings split, EPF on Basic, ESI, employer contribution, one-cycle adjustments) live in the pure `src/hrms/payslip.js` module with node tests; per-staff structure and per-cycle adjustments are jsonb on `hr_staff` so finalized `hr_payslips.summary` freezes them.
- Shift plan files: layout, checks and change list live in the pure `src/hrms/shiftPlan.js` (node tests); `src/hrms/shiftPlanFile.js` writes/reads .xlsx/.xls/.csv (lazy-loaded). Managers write `hr_roster` only for their reports, today onward, unfinalized cycles (RLS, migration 0021); a roster `WO` is a planned weekly off read by `normalizePunches(…, {plan})`.
- Withdrawing approved leave/permission: window and attendance restore rules live in the pure `src/hrms/leaveRevoke.js` (node tests); approval saves the day on `hr_leaves.prev_attendance`; the `hr_leaves_guard` trigger (migration 0022) enforces Approved → Revoked only, running/previous cycle only, not in a finalized cycle.
- Multi-unit staff: gap and coverage rules live in the pure `src/hrms/multiUnit.js` (node tests); `hr_staff.multi_unit` and `hr_import_log` (migration 0023). The import merge itself stays in `mergeAttendanceRecord` (punches.js).
- Weekly off with effective dates: `weeklyOffOn(base, history, date)` in `src/hrms/punches.js`; `hr_staff.weekly_off` is the day from the start, `hr_weekly_off` rows change it from `effective_from` (managers: own staff, today onward — RLS, migration 0024). Every `normalizePunches` call passes `weeklyOffHistory`. It also passes `shiftContext(staff, SHIFT_MASTER)`: a lone evening punch starts a night shift only when a night shift is planned that day (or nothing is planned and the person is not on a General Shift); otherwise it is the OUT of a day with a missing IN.
- Top administrator as reporting manager: `hr_staff.reporting_manager = '@top'` (TOP_MGR, port_prototype.py section 55) means the Payroll Settings "Top administrator" (no staff code); offered in every reporting-manager list, resolved by `topManagerFor`, and their requests go to administrators.
- Approved leave set by the reporting manager: leave type and attendance status `AL` (migration 0027, trigger `hr_leaves_al_guard`: running/previous cycle, up to today, not finalized); `absencesForLeave` and the window live in the pure `src/hrms/leaveRevoke.js` (node tests). An `AL` day is paid and does not use CL; it is withdrawn like any approval. The same dialog sets a week off: leave type `WO` (migration 0028) whose effect is a past-day roster `WO` (managers may insert/remove only `WO` on past days in that window — RLS); withdrawing removes that roster `WO`.
- Admin notifications: `hr_notifications` (migration 0026) holds tasks for one administrator account (`recipient_email`; RLS: an admin reads and updates only their own, any admin can send), each with steps, staff items and the admin tab to open. The bell in the admin header (port_prototype.py section 54) lists them and marks them read or done.
